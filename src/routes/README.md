# src/routes

Express `Router()` instances, one per resource group, each composing its own middleware chain per-endpoint (`requireAuth`/`requireAdminAuth`, `requireDb`, a rate limiter, `validateParams`/`validateBody`, then the controller) — there's no single global auth/validation gate, every route explicitly lists what it needs. All mounted in `src/routes/index.ts`'s `registerRoutes(app)`, which is itself called near the bottom of `src/app.ts` (after `helmet`, CORS, and the two raw-body webhook routes that must be registered *before* the global `express.json()` middleware).

| Prefix | Router file | Covers |
|---|---|---|
| `/health` | `health.routes.ts` | `GET /` — liveness check, no auth, no DB dependency. |
| `/auth` | `auth.routes.ts` | Signup/login/refresh/logout, Google OAuth, email verification (link *and* OTP), password forgot/reset (canonical `/password/forgot|reset` + legacy `/forgot-password`/`/reset-password` aliases, same handlers), auto-purchase toggle. See `src/validators/README.md` for the OTP purpose split. |
| `/chatbots` | `chatbot.routes.ts` (by far the largest — one router per *sub-feature* of a chatbot, all nested under `/:chatbotId`) | Core CRUD + status; `usage` (day/week/month summaries); `analytics`; `live-data` CRUD; `integration` (per-chatbot encrypted backend API key); `actions` CRUD (active Crawl Plus plus a Claude/OpenAI top-up); `documents` CRUD (Crawl Plus+ ingestion); `woocommerce` connect/status/sync/disconnect; `bookly` connect/status/disconnect + `bookly-admin-chat` + `bookly-admin-audit-log`; theme/domain/fallback-message/preferred-model PATCH endpoints; `chat` (authenticated dashboard preview, rate-limited via `rateLimitAuthenticatedChat`). |
| `/billing` | `billing.routes.ts` | `GET /summary`, `POST /checkout-session` (+ `/checkout` alias — same handler, added to match the frontend's preferred call shape), `POST /portal-session` (Stripe customer portal), `POST /chatbots/:chatbotId/topup`. The browser only ever sends a plan *code*; the real Stripe Price ID is resolved server-side (`src/lib/stripe.ts`) — see `src/validators/README.md`'s billing note. |
| `/notifications` | `notifications.routes.ts` | `GET /`, `POST /read-all`, `POST /:id/read` — dashboard notification inbox. |
| `/webhooks/stripe`, `/webhooks/woocommerce/:chatbotId` | mounted directly in `src/app.ts`, not a `routes/*.ts` file | Both need the **raw**, unparsed request body for signature verification (`express.raw()`), so they're registered ahead of the global `express.json()` middleware — grep `app.ts` for `express.raw` before assuming every route sees a parsed JSON body. |
| `/waitlist`, `/trial`, `/contact`, `/demo` | one-route-each files | Public marketing-site forms / the sandboxed demo chat (`src/data/README.md`). No auth, no chatbot ownership. |
| `/public` | `public.routes.ts` | The embeddable widget's own API surface: `GET /chatbots/:chatbotId` (widget config), `POST /chatbots/:chatbotId/chat`. No `requireAuth` — authorization here is per-chatbot `allowed_domain` origin-checking (`src/services/public.service.ts`), not a login. Sets `Cross-Origin-Resource-Policy: cross-origin` on every response in this router so the widget iframe (a different origin than the API, by design — see `src/public/README.md`) can use it. |
| `/admin` | `admin.routes.ts` | A **separate** JWT namespace (`requireAdminAuth`, `typ: "admin"` tokens — mutually rejected with customer `typ: "access"` tokens, see `src/middleware/README.md`). Login, list/deactivate/activate/delete users (delete requires an explicit `confirm: true` body — the schema itself enforces this, not just the controller), per-user usage, abuse-flag list/review. |

**Convention if you add a new route file**: import it into `routes/index.ts` and mount it there — there is no auto-discovery of route files. Keep the router's own file focused on wiring (which middleware, in which order, calling which controller) — validation logic belongs in `src/validators/`, business logic in `src/services/`; a route handler function should never appear directly in a `routes/*.ts` file (that's what `src/controllers/` is for).
